# StudySprint — Syllabus Intelligence Engine (Future Research)

**Status:** Parked / not part of V1  
**Product rule:** Do not show Syllabus Intelligence in the current StudySprint UI, navigation, onboarding or V1 marketing. This document preserves a future research direction only.

## 1. Future objective

When this engine is prioritized, it may convert a university/course syllabus into a structured, editable map of units, topics, subtopics, learning outcomes and assessment weightage. It should help connect what a course officially teaches with what historical question papers actually test.

It must not be built into V1 merely because the future design is documented.

## 2. Possible inputs

- Official syllabus PDF or text
- University, program, course, semester and syllabus version
- Course outcomes and unit-wise weightage, when explicitly present
- Optional official curriculum metadata supplied by the user

Every extracted item must retain its source page / section where possible.

## 3. General algorithm candidates (not selected)

| Problem | Candidate approach | Validation needed |
|---|---|---|
| PDF text extraction | PDF.js or server-side PDF parser | Reading order, columns, tables, page references |
| Structure detection | Rules for unit/module headings, numbering and course-outcome labels | Compare against manually annotated syllabi |
| Topic hierarchy | Gemini structured extraction into unit/topic/subtopic schema | Completeness, hierarchy correctness, no invented topics |
| Duplicate topic resolution | Normalized text + semantic similarity review | Avoid merging related but distinct concepts |
| Learning outcome mapping | Gemini proposes mappings with quoted evidence | Human verification and source traceability |
| Syllabus version comparison | Deterministic tree diff | Detect moved, renamed, added and removed topics |

## 4. Future relationship with PYQ Intelligence

The long-term opportunity is a cross-engine mapping:
- syllabus topic → official unit and source location
- PYQ question → extracted question and source paper
- topic match → explicit mapping with confidence and evidence

A future combined report could show:
- syllabus coverage: official topics represented in the uploaded PYQ set
- historical paper coverage: how many uploaded papers contain questions mapped to a syllabus topic
- untested-in-upload-set topics (not "unimportant" topics)
- recurring questions outside the supplied syllabus (possible syllabus mismatch requiring review)

The two engines must remain independently testable. A weak syllabus extraction must not contaminate PYQ counts.

## 5. Non-negotiable truth rules

- Never invent a unit, topic, course outcome, weightage or page reference.
- Preserve original syllabus wording beside normalized labels.
- Distinguish explicit official weightage from inferred importance.
- Do not infer that a topic is excluded simply because it is absent from the document text.
- Keep human editing and approval before using syllabus mappings in reports.

## 6. Priority gate before implementation

Do not start implementation until:
1. PYQ Intelligence V1 has been tested with real papers from multiple course formats.
2. A labelled syllabus benchmark is collected.
3. Topic extraction precision and recall are measured.
4. Users explicitly validate that syllabus mapping solves a real workflow problem.
5. The team agrees on the data model and versioning strategy.

## 7. Future research questions

- Which PDF extraction approach handles university syllabus layouts most reliably?
- Should topic hierarchy be generated by Gemini JSON schema, constrained grammar or a hybrid?
- How should syllabus versions and university curriculum revisions be represented?
- How can the system distinguish official course outcomes from model-inferred learning objectives?
- What is the right confidence threshold for auto-accepting a syllabus topic?
